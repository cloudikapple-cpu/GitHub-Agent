# v0.3 — autonomy pack

Everything added on top of v0.2, and how to switch it on.

## 1. Internet through Tavily

Tavily is a search API built for agents: ranked results, clean text and an
optional synthesised answer.

```bash
TAVILY_API_KEY=tvly-...
```

`web_search` uses Tavily when the key is present and silently falls back to
DuckDuckGo otherwise, so search never breaks. `web_fetch` first tries Tavily's
extractor (handles JS-heavy pages), then a plain HTTP fetch.

```yaml
search:
  provider: auto      # auto | tavily | duckduckgo
  max_results: 5
  depth: advanced     # slower, digs deeper
```

## 2. MCP client

Any MCP server becomes Jarvis tools — GitHub, Notion, Postgres, Puppeteer,
your own. stdio and HTTP transports, no extra dependency.

```yaml
mcp_servers:
  github:
    command: npx
    args: ["-y", "@modelcontextprotocol/server-github"]
    env:
      GITHUB_PERSONAL_ACCESS_TOKEN: ${GITHUB_TOKEN}
```

Tools appear as `github_create_issue`, `github_search_code`, ... A server that
fails to start is skipped with a warning.

## 3. Long-term memory

`remember` / `recall` / `forget` back onto a local SQLite vector store
(`~/.jarvis/knowledge.db`). Before each run the agent quietly recalls the notes
relevant to your message and adds them to the context.

Embeddings use your provider's `/embeddings` endpoint when configured, and an
offline hashing embedder otherwise — no cloud call, no extra package.

## 4. Reminders and scheduled tasks

```
remind me in 15m to check the deploy
remind me every day at 09:00 to review the inbox
run "summarise yesterday's commits" every day at 20:00
```

* `remind_me` — desktop notification, spoken when voice is on;
* `schedule_task` — the daemon runs the prompt unattended;
* `list_jobs` / `cancel_job` — management.

Jobs live in `~/.jarvis/jobs.json` and survive restarts. The scheduler runs
inside `jarvis --daemon`.

## 5. Vision

```yaml
vision:
  enabled: true
  provider: openai
```

`see_screen` takes a screenshot and asks a vision model about it;
`look_at_image` does the same for a file. Handy for "what does this error
say?" without copy-pasting.

## 6. Execution sandbox

```yaml
execution_sandbox:
  mode: docker        # none | docker | firejail
  image: python:3.12-slim
  network: false
```

`run_shell` and `run_python` then execute inside a container (or a firejail
profile) with no network and a memory cap. Or per run: `jarvis --sandbox docker`.

## 7. Tray icon and autostart

The daemon shows a tray icon (Ask Jarvis / Voice command / Quit) when `pystray`
is installed. Start it with the system:

```bash
jarvis --autostart install   # remove | status
```

## 8. Interruptible runs

`Ctrl+C` in the REPL, or `agent.cancel()` from any interface, stops the loop at
the next safe point instead of killing the process.

## 9. Multi-agent delegation

The `delegate` tool hands a self-contained subtask to a helper agent with its
own context, optionally on a cheaper provider:

> delegate: "read every .py in ./jarvis and list the TODOs", provider: "ollama"

Depth is capped at two levels so helpers cannot spawn helpers forever.

## 10. Dry run

```bash
jarvis --dry-run -m "clean up my Downloads folder"
```

The model returns a numbered plan naming each tool and its arguments, and
executes nothing.

## 11. Telegram

```bash
JARVIS_TELEGRAM=true TELEGRAM_BOT_TOKEN=... TELEGRAM_ALLOWED_USERS=123456789
jarvis --telegram        # or automatically inside --daemon
```

Only whitelisted user ids are served. Tools that need confirmation are refused
by default, since a chat cannot show a dialog.

## 12. Local model + NVIDIA NIM

```yaml
router:
  enabled: true
  primary: ollama     # free, private, offline
  fallbacks: [nim]    # NVIDIA NIM when the local one is down
  heavy: nim          # long or explicitly hard requests
  escalate_over_chars: 4000
```

The router remembers which provider answered, so the UI can show it. Turn it
on for a single run with `jarvis --router`, off with `--no-router`.
